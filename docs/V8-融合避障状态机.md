# V8：把视觉版的闭环绕障逻辑移植到超声波车

> 这一版只动"避障"部分：循迹 PID（IRSEARCH）一行没改，
> 引脚、定时器、舵机、超声波的接线全部保持原样。
>
> 目标不是"能绕一次"，而是让 循迹 → 减速 → 绕障 → 越过 → 找线 → 对正 → 恢复
> 这条链路上每一步都有明确的进入条件和退出条件，并且任何一步卡住都能安全停车。

---

## 1. 原来的五态为什么绕不稳

原实现是 `SYSTEM/app/app_mode.c` 里的 `mode1_update()`，
五个状态：`FUS_LINE → FUS_SCAN → FUS_TURN → FUS_SEEK → FUS_COOLDOWN`。

| # | 问题 | 代码位置 | 后果 |
|---|---|---|---|
| 1 | 触发即 `Motor_Stop()`，没有减速段 | 原 `mode1_update()` LINE 分支 | 60 的 PWM 直接掉到 0，再突然给 85，车身一顿一冲 |
| 2 | 转向纯定时 600ms | `FUS_TURN_MS` | 电池电压降一点、地面滑一点，转角就变；没有角度反馈 |
| 3 | 越障完成没有任何确认 | TURN 结束直接进 SEEK | 可能还贴着障碍物就开始找线 |
| 4 | 找线是"原地反向转 2.5s"，超时**静默回循迹** | `FUS_SEEK_TIMEOUT_MS` | 线在车尾方向时会一直打转；超时后带着错误朝向回 PID，直接冲出去 |
| 5 | 重触发抑制只有 400ms | `FUS_COOLDOWN_MS` | 绕完还在障碍旁边，立刻二次触发，来回摆 |
| 6 | 测距用 `AVoid_Measure()` 忙等最多 30ms | `IRAvoid.c` | 10ms 节拍被拖成 40ms，所有 ms 定时实际都偏长 4 倍 |
| 7 | 两侧都 <20cm 就原地掉头 | `Motor_SetSpeed(-55,55)` | 车尾可能撞墙，且掉头后朝向完全不可控 |
| 8 | 电机输出是阶跃 | `Motor_SetSpeed(0,85)` | 轮子打滑，实际转角比预期小 |

> 一句话：**"什么时候算绕过去了"没有传感器回答，全靠 ms 猜。**

## 3. 状态机

```
        ┌──────────────────────────── 恢复 ────────────────────────────┐
        │                                                              │
     ┌──▼───┐  40cm  ┌──────┐  22cm×2  ┌──────────┐ 300ms ┌───────┐    │
     │ LINE │───────►│ SLOW │─────────►│ TURN_OUT │──────►│ SHIFT │    │
     └──▲───┘ 60%速  └──┬───┘  侧向已测 └──────────┘       └───┬───┘    │
        │               │ 1.5s 没靠近→回 LINE                   │ 550~1000ms
        │               └──────────────────────────────────┐    │ 或灰度离线3拍
        │                                                  │    ▼
        │            ┌──────┐ 700ms  ┌───────────┐ 320ms ┌────────────┐
        │            │ COOL │◄───────│  ALIGN    │◄──────│STRAIGHTEN  │
        │            └──┬───┘ 3拍对正 └─────▲─────┘       └─────┬──────┘
        │  700ms 爬坡   │                  │ 3拍见线              │
        └───────────────┘            ┌─────┴────┐  700ms 且前方≥45cm×3
                                     │   SEEK   │◄────────────────┘
                                     └──────────┘        （PASS）
```

### 进入/退出条件

| 状态 | 进入 | 退出 |
|---|---|---|
| `FU_LINE` | 上电 / COOL 结束 | 前方 ≤`FU_SLOW_CM`(40) 连续 2 帧 → SLOW；或链路/灰度故障 → FAULT |
| `FU_SLOW` | 目标进入 40cm | 前方 ≤`FU_TRIGGER_CM`(22) 连续 2 次 → TURN_OUT；1.5s 内没靠近 → 回 LINE |
| `FU_TURN_OUT` | 确认要绕 | 300ms（转向斜率受限）→ SHIFT |
| `FU_SHIFT` | 转向完成 | ≥550ms **且**（灰度连续 3 拍离线 或 ≥1000ms）→ STRAIGHTEN |
| `FU_STRAIGHTEN` | 侧移够远 | 320ms → PASS |
| `FU_PASS` | 车头回正 | ≥700ms **且** 前方 ≥45cm 连续 3 次 → SEEK；≥2200ms 仍被挡 → FAULT(BLOCKED) |
| `FU_SEEK` | 越过障碍 | 灰度见线连续 3 拍 → ALIGN；3s 找不到 → FAULT(TIMEOUT) |
| `FU_ALIGN` | 见到线 | 线在中心 ±25 内连续 3 拍 → COOL；连续 3 拍丢线 → 回 SEEK；600ms → 回 SEEK |
| `FU_COOL` | 对正完成 | 700ms 内速度 55%→100% 爬坡（PID 已接管）→ LINE |
| `FU_FAULT` | 任何超时/异常 | **不自动恢复**，停车 + 关限速 + 舵机回中，需重新按 `1` |

### 为什么"侧移完成"用灰度判断

旧代码侧移 600ms 就走，走多远取决于电压和地面。
本版在 `FU_SHIFT` 里每 10ms 读一次灰度：
**连续 3 拍（30ms）完全看不到线** 才认为"已横向让开"，
这样侧移量由"线离开视野"这个物理事件决定，而不是由定时器决定。
1000ms 只是兜底（比如线特别宽、或者车身压着线走）。

### 为什么"越过障碍"用超声波判断

`FU_PASS` 要求前方 **≥`FU_CLEAR_CM`(45cm) 连续 3 次**才认为越过了。
和旧版的"转向 600ms 后就当过了"相比，这是**用传感器回答"过了没有"**，
而不是用时间猜。超过 2.2s 还一直 <45cm → 判定被挡死，安全停车。

## 4. 参数（全在 `SYSTEM/fusion/fusion_avoid.h`）

| 宏 | 默认 | 含义 | 怎么调 |
|---|---|---|---|
| `FU_SLOW_CM` | 40 | 开始减速的距离 | 车太快冲过头 → 调大(50)；太早减速 → 调小(35) |
| `FU_TRIGGER_CM` | 22 | 正式提交绕行的距离 | 撞上才转 → 调大(28)；离得远就转 → 调小(18) |
| `FU_CLEAR_CM` | 45 | 判定"已越过"的清空距离 | 还没过就往前走 → 调大(55) |
| `FU_SIDE_NEAR_CM` | 25 | 选定侧向小于它 → 换一边绕 | 老撞侧面 → 调大(30) |
| `FU_SLOW_PCT` | 60 | 减速时保留的基础速度百分比 | 减速太猛点头 → 调大(70) |
| `FU_SHIFT_MIN_MS` | 550 | 侧移最短时间 | 侧移不够 → 调大(650) |
| `FU_SHIFT_MAX_MS` | 1000 | 侧移兜底时间 | 车很慢时调大 |
| `FU_PASS_MS` | 700 | 越障最短时间 | 车头还没过就找线 → 调大(900) |
| `FU_PASS_MAX_MS` | 2200 | 越障超时 → 判定被挡 | 长障碍 → 调大 |
| `FU_SEEK_BUDGET_MS` | 3000 | 找线预算 | 线离得远 → 调大 |
| `FU_COOLDOWN_MS` | 700 | 恢复冷静期 + 爬坡 | 刚上线又触发 → 调大(1000) |
| `FU_REARM_MS` | 1200 | 重新武装所需"前方无近物"时长 | 同一个障碍反复触发 → 调大(1800) |
| `FU_SLEW_STEP` | 12 | 每 10ms 允许的 PWM 变化量 | 起步打滑 → 调小(8)；反应迟钝 → 调大(16) |

### 调参顺序（只按这个顺序来，别一次改五个）

1. **先标定距离**：车停 40cm / 22cm / 45cm，串口看 `dist=`，不对就改 `FU_*_CM`
   （`dist` 是超声波原始 cm，不用标定像素；只要确认 `AVoid_GetDistance()` 数值可信）。
2. **`FU_SLOW_CM`**：让车在障碍前明显减速，但不要提前太多。
3. **`FU_TRIGGER_CM`**：以"转向时车头离障碍还有 15~20cm"为准。
4. **`FU_SHIFT_MIN_MS`**：绕完车身与黑线的横向距离 ≥ 一个车身。
5. **`FU_SEEK_BUDGET_MS`**：确认 3s 内一定能压到线（压不到说明侧移太多，回头调 4）。
6. 最后才碰 `FU_SLEW_STEP` 和 `FU_SLOW_PCT`。

## 6. 串口看什么

`DEBUG_UART = 1` 时每秒一行，原来的 `fus=%d` 现在是状态号（1=LINE … 10=FAULT），
`dist=` 是超声波 cm（`0` 表示没回波）。

关键事件会额外打（只在切换瞬间）：

```
[fus] LINE->SLOW d=38
[fus] SLOW->TURN_OUT d=21 side=1 side_d=46
[fus] FAULT 1        ← FF_BLOCKED：越障超时仍被挡
[fus] FAULT 2        ← FF_TIMEOUT：找线 3s 失败 / 全程 9s 超时
[fus] FAULT 3        ← FF_GRAY：灰度连续 15 拍读不到（I2C 掉线）
```

## 7. 测试

### 宿主机单测（不用车）

```bash
cd "/c/stm32&c51/ZYSTM32-A0"
python tests/test_fusion.py
```

它把 `fusion_avoid.c` 的 `#include` 去掉，拼上打桩的电机/灰度/超声波，
用 gcc 编译后跑：减速→提交→侧移→越障→找线→对正→恢复全链路，
以及斜率限制、重触发闩锁、BLOCKED/TIMEOUT/GRAY 三种故障、Stop 停车。

脚本会**编两遍**：默认（定时转角）跑上面全部用例，再带 `-DFU_YAW_TURN=1`
跑 §9 的转角闭环用例（按角度退出、回正回提交航向、陀螺卡死退回定时）。

> 这一步只能证明**逻辑**对，证明不了**几何**对（转角、侧移量要上车调）。

### 上车测试

1. **静态**：车架空，按 `1`，手在车前 40cm 晃 → 串口应打 `LINE->SLOW`，轮子降到 60%。
   手推到 22cm → 应打 `SLOW->TURN_OUT`，舵机先向绕行侧摆、250ms 后回中。
2. **直线单障碍**：胶带直线中间放杯子，看是否减速、绕开、**停车前不再贴杯**。
3. **恢复**：绕完后车应自己向线的方向画个小弧、压线、正对，再加速到原速。
   若压线后猛地一甩 → `FU_COOLDOWN_MS` 调大，或检查 `FU_ALIGN_DEADBAND`。
4. **重复性**：同一位置连跑 10 次，至少 9 次不碰障碍、9 次能回到线。
5. **故障**：绕行中拔掉 K210/灰度线 → 应停车并打 `FAULT 3`，不会乱跑。
6. **两侧都堵**：杯子 + 墙夹住通道 → 应停车（`FAULT 1`），**不再原地掉头**。

## 8. 已知边界

- **没有侧向距离闭环**：`FU_PASS` 只看正前方。想在贴障碍时自动往外修，
  需要"舵机偏转 + 采一次侧向距离 + 回中"的时分复用，本版没做（会拖慢越障判定）。
- **单超声波盲区**：探头高度以下的矮障碍、细杆、吸声材质（布/海绵）测不到或测短。
  贴地胶带、纸箱、塑料杯这类是可以的。
- **转角默认仍是定时**：`FU_TURN_OUT` / `FU_STRAIGHTEN` 出厂走"斜率受限的定时"。
  航向闭环已经写好、挂在 `FU_YAW_TURN` 开关后面（见 §9），默认关——没有实车时
  打开的转角几何没人验证过，宁可先不动。等上车量出"转 55° 到底该转多少"再开。
- **`FU_SLOW` 里的侧向探测要 250ms**，这期间车还在以 60% 前进（约 7~8cm）。
  车很快时把 `FU_SCAN_SETTLE_MS` 调小，或把 `FU_SLOW_CM` 调大留出余量。

## 9. 可选：转角用陀螺闭环（`FU_YAW_TURN`）

出厂 `FU_YAW_TURN = 0`，和 §1~§8 描述的定时转角完全一致。它的作用只有一个：
**把"转 300ms 大概转了多少度"换成"转够 55° 就走"**，车快车慢、电池新旧都不影响转角。

### 打开

改 `SYSTEM/fusion/fusion_avoid.h`：

```c
#define FU_YAW_TURN         1
```

或者在 Keil 的 *Options → C/C++ → Define* 里加 `FU_YAW_TURN=1`（头文件用 `#ifndef`
保护过，两种都行），不用动源码。

### 打开后的行为

- `FU_TURN_OUT`：进状态时锁存 `yaw0`，转到 `yaw0 ± FU_TURN_DEG` 就进 `FU_SHIFT`；
  不再看 `FU_TURN_OUT_MS`。兜底 `FU_TURN_OUT_MAX_MS = 800ms`。
- `FU_STRAIGHTEN`：往回转，转到回到 `yaw0` 附近（±`FU_YAW_TOL_DEG`）才进 `FU_PASS`；
  兜底 `FU_STRAIGHTEN_MAX_MS = 800ms`。
- **陀螺不可用时自动退回定时**：`Imu_IsReady()` 为假，或车已经在转但 150ms 内角度
  涨不到 8°（陀螺卡死 / I2C 断了），这一段就退回原来的 300ms / 320ms 定时逻辑，
  不会因为陀螺坏了把车卡在转角里。

| 宏 | 默认 | 含义 |
|---|---|---|
| `FU_TURN_DEG` | 55 | 绕行侧转出角，右绕对称取负 |
| `FU_YAW_TOL_DEG` | 6.0 | 角度到位死区 |
| `FU_YAW_STALL_MS` / `FU_YAW_STALL_DEG` | 150 / 8.0 | 判定"陀螺没跟上" |
| `FU_TURN_OUT_MAX_MS` | 800 | 转出兜底（有陀螺时才生效） |
| `FU_STRAIGHTEN_MAX_MS` | 800 | 回正兜底 |

### 上车前必须先验证方向（很重要）

1. 车架空，控制台把 `Imu_IsReady()` 打出来，确认为 1；用 `Imu_GetYaw()` 打角度。
2. 手推车头**向左**转 90°，看串口 `yaw` 是不是**变大**（V7 的 `IMU_YAW_SIGN` 已经按
   左转为正配好，但每块板子的贴片方向可能不同）。
3. 若方向反了，改 `SYSTEM/imu/imu.c` 里的 `IMU_YAW_SIGN`（1 → -1），**不要**在
   `fusion_avoid.c` 里取反，否则两个模块的语义会打架。
4. 方向对了再打开 `FU_YAW_TURN`；先低速试一次绕障，看串口 `[fus]` 里 TURN_OUT
   停留的时间是否随电池电压变化而基本不变。

### 为什么默认关

- 55° 这个数是拍的。真实赛道要的是"绕出去之后车身正好离开线外侧"，跟轮距、
  车速、侧移距离都有关，只能上车量。
- 定时版虽然不精确，但**每次行为一致**，比赛时更容易调；陀螺版一旦符号/零偏有问题，
  表现是"转过头"或"转不动"，比定时更吓人。
- 关着的时候代码路径和 V8.0 完全相同，不存在回归风险；打开是纯增益选项。

宿主机单测覆盖了三种情况（`python tests/test_fusion.py` 里会编两遍）：
陀螺正常时按角度退出、回正回到提交航向、陀螺卡死时退回定时。
