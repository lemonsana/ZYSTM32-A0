# 陀螺仪与编码器（V6.0，编码器在 V6.1 改过脚）

> V6.0 = V5（5ms 调度 + 模式表 + 高速过弯）+ MPU6050 陀螺仪 + 双增量编码器。
> V5 的电机符号、灰度极性、循迹内核一行没动 —— **V5 能跑，V6.0 就还能跑**。
> 两个新模块默认"只测不用"：驱动跑起来、串口能看到数据，但不参与控制。

## 2. 接线表

### 陀螺仪 MPU6050（软件 I2C，PC0/PC1）

| 模块引脚 | 接板子 | 说明 |
| --- | --- | --- |
| VCC | 3.3V | 模块自带 LDO 的话 5V 也行，**不确定就接 3.3V** |
| GND | GND | 共地必须接 |
| SCL | **PC0** | 软件 I2C 时钟 |
| SDA | **PC1** | 软件 I2C 数据 |
| AD0 | GND（或不接） | 接地 = 地址 `0x68`；接 3.3V = `0x69`（要改 `GYRO_I2C_ADDR`） |
| INT | 不接 | 本驱动纯轮询，不用中断 |
| XDA/XCL/XCLR | 不接 | 本驱动不挂从机 |

> 超声波 HC-SR04 原来就是 PC0(TRIG)/PC1(ECHO)，V6.0 起**已被移除**。
> 想恢复超声波：把 `SYSTEM/IRAvoid/IRAvoid.h` 的 `AVOID_HW_ENABLE` 改成 1，
> 但那样就得把陀螺仪从 PC0/PC1 上拔掉（两只模块抢同一对脚）。

### 编码器（PA0/PA2 + PA7/PA8 —— 全在 P2 排针）

| 编码器 | 引脚 | 板上位置 | 实现方式 |
| --- | --- | --- | --- |
| 左轮 A 相 | **PA0** | P2 排针第 3 脚 | EXTI0 软件正交解码（4 倍频） |
| 左轮 B 相 | **PA2** | P2 排针第 2 脚 | EXTI2 |
| 右轮 A 相 | **PA7** | P2 排针第 4 脚 | EXTI7 |
| 右轮 B 相 | **PA8** | P2 排针第 7 脚 | EXTI8，与 PA7 共用 `EXTI9_5_IRQHandler` |

**供电：`编码器正极` 接 3.3V（CN3 的 VCC3.3），`编码器负极` 接 GND。**
松甲这款是「13 线霍尔 + 带上拉输出」，A/B 直接进单片机就行，**不用外加上拉电阻**
（固件里这 4 只脚也统一配成了上拉输入，算双保险）。

> ！**为什么不用手册写的 5V 供电**：A/B 的电平跟着编码器自己的供电走。这套方案里
> PA8 是 5V 容忍（FT），但 **PA0/PA2/PA7 不是 FT**（数据手册表5 只写 `I/O`），
> 5V 上拉输出直连会倒灌。所以要么 3.3V 供电（推荐，实测能正常输出），
> 要么 5V 供电 + A/B 各串 1kΩ 分压。

原厂 PH2.0-6P 线的顺序是：`电机线+ / 编码器负极 / 编码器B相 / 编码器A相 / 编码器正极 / 电机线-`，剪线后按这个对：

| 原厂线 | 接到 |
| --- | --- |
| 电机线+ / 电机线- | 电机驱动板输出（**不是**单片机） |
| 编码器负极 | GND（必须和单片机共地） |
| 编码器正极 | 3.3V（CN3 的 VCC3.3） |
| 编码器 A 相 | PA0（左轮）/ PA7（右轮） |
| 编码器 B 相 | PA2（左轮）/ PA8（右轮） |

A/B 接反不用拆线，把 `ENC1_SIGN` / `ENC2_SIGN` 改成 -1 即可。

### 板上排针在哪接（照商家原理图核过）

主控 STM32F103RCT6，板上共四组排针（依据 `赛事工程\…\5.原理图\ZYSTM32-A0原理图.pdf`）：

| 排针 | 脚位 → 信号 |
| --- | --- |
| **CN1**（1×6） | 1=PC0　2=PC1　3=PC2　4=PC3　5=PA1　6=PC5 |
| **CN2**（2×8） | 1=PA10　2=PA9　3=PD2　4=PC10　5=PC15　6=PC14　7=PB10　8=PB11<br>9=PB12　10=PB13　11=PB14　12=PB15　13=PC6　14=PC7　15=PC8　16=**GND** |
| **P2**（1×8） | 1=PA3　2=PA2　3=PA0　4=PA7　5=PB0　6=PB1　7=PA8　8=PB6 |
| **P3**（1×10） | PB7 / PB8 / PB9 / PA4 / PA6 / PA5 / PB5 / PB11 / PB10 各一脚，另有 **GND** |
| **CN3**（1×8） | 电源与启动：**VCC5**、**VCC3.3**、**GND**、VIN、RESET、BOOT0 |

**实测结论：这四只脚最后落在 P2 排针上**（舵机 PB0 就在同一排，是唯一确定能用的排针行）：

| 信号 | P2 脚 | MCU 脚 |
| --- | --- | --- |
| 编码器1 A | 3 | PA0 |
| 编码器1 B | 2 | PA2 |
| 编码器2 A | 4 | PA7 |
| 编码器2 B | 7 | PA8 |
| 两个编码器的负极 | 从 P3 的 GND 脚取 | GND |
| 两个编码器的正极 | 从 CN3 的 **VCC3.3** 取 | 3.3V |

> **走过的弯路（供后来人省事）**：最早按原理图用 PC6/PC7（TIM8 硬件正交）+ PC8/PC9；
> 后来发现 **PC9（芯片 pin 40）整根线悬空**，没引到任何排针；再换成 PB14/PB15（CN2 的 11/12 脚），
> 实物板上依然找不到。所以 V6.1 起两路全部落到 P2 排针的 PA0/PA2/PA7/PA8，
> TIM8 硬件正交解码改成 EXTI 软件解码（`encoder.h` 里 `ENC1_USE_TIM8` 保持 0）。
>
> **5V 容忍看数据手册表5**：PC6~PC12、PB2~PB15、PD2、PA8~PA15 标 `I/O FT`；
> **PA0/PA2/PA7 只写 `I/O`，不是 5V 容忍**（PA8 是）。**PC0~PC5 也全不是 FT** ——
> 陀螺仪 PC0/PC1 同样只能 3.3V。

## 3. 资源核对（这是最该先看的一节）

### 串口够不够？—— **编码器根本不占串口**

| 资源 | 现状 | 结论 |
| --- | --- | --- |
| USART1（PA9/PA10，板载 CH340G） | 调试口，115200 | 完全不受影响，V6.0 的 BOOT / 三行调试打印都从这走 |
| USART2（PA2/PA3） | 空着 | 想接蓝牙/WiFi 随时能用 |
| USART3（PB10/PB11） | **被灰度传感器 I2C 占着** | 不能用 |
| 编码器 | 只用 4 个 GPIO + EXTI | **不占任何串口** |

所以"串口够不够"这个担心可以放下：两个编码器走的是定时器和外部中断，一个串口都不用。

### 引脚

| 引脚 | V5 用途 | V6.0 变化 |
| --- | --- | --- |
| PA1 | 红外遥控 TIM5_CH2 | 不变 |
| PA4 / PA6 | 右电机方向 / LED D4 | 不变 |
| PA9 / PA10 | USART1 TX/RX | 不变 |
| PB0 | 舵机 TIM3_CH3 | 不变 |
| PB1 | 红外避障探头 | 不变 |
| PB6 / PB7 | LED D3 / 左电机方向 | 不变 |
| PB8 / PB9 | 右/左电机 PWM（TIM4） | 不变 |
| PB10 / PB11 | 灰度 I2C | 不变 |
| PC0 / PC1 | 超声波 TRIG/ECHO | **改接 MPU6050 SCL/SDA** |
| PC2 / PC3 | 模式按键 / 蜂鸣器 | 不变 |
| PA0 / PA2 | 空 | **编码器1 A/B（EXTI0/EXTI2，P2 第 3/2 脚）** |
| PA7 / PA8 | 空 | **编码器2 A/B（EXTI7/EXTI8，P2 第 4/7 脚）** |
| PC6~PC9 | 空 | 原理图上属 CN2，**实物板没引出，不用** |
| PB14 / PB15 | 空 | 同上，没引出 |

### 定时器与中断

| 定时器 | 用途 |
| --- | --- |
| TIM6 | 5ms 节拍（`Sched_Init`），无引脚 |
| TIM4 | 电机 PWM |
| TIM5 | 红外遥控输入捕获 |
| TIM3 | 舵机 50Hz |
| TIM8 | **未用**（编码器改 EXTI 后不再占定时器） |
| TIM2 | 随超声波关闭而**空出**，可用 |
| TIM1 / TIM7 | 未用 |

中断：`EXTI0_IRQHandler` + `EXTI2_IRQHandler`（编码器1 的 PA0/PA2）、`EXTI9_5_IRQHandler`（编码器2 的 PA7/PA8，抢占 1 / 子优先级 1）、`EXTI1_IRQHandler`（随超声波一起编译掉）、USART1、TIM5 捕获。

固件体积：V5 = `Code 16370`，V6.0 = `Code 25214`（+8844 字节，大头是 `atan2`/`sqrt` 拉进来的双精度数学库）。Flash 256KB，随便塞。

## 4. 陀螺仪 MPU6050

### 4.1 上电自检

上电后串口会多打两行：

```
[BOOT] gyro ready = 1 id=0x68  (0x68 = MPU6050)
[BOOT] encoder L=0 R=0  second=0
```

- `ready = 0` 或 `id = 0x00 / 0xFF` → **I2C 没通**，先查 PC0/PC1 是否接反、模块有没有供电（0x75 寄存器读不到就是硬件问题，别急着改代码）。
- `id = 0x69` → AD0 接了 3.3V，改成 `#define GYRO_I2C_ADDR 0x69`。
- 上电到 `Sched_Start()` 之间约有 **0.6 秒**用于陀螺仪复位（100ms）+ 零偏校准（200 次 × 2ms），这段时间车是不动的，属正常。

### 4.2 调试第三行怎么读

`app_mode_debug_task` 每 200ms 打三行，第三行是 V6.0 新增：

```
yaw=   -3 pit=   1 rol=   0 gz=    2 | g=1 encL=   0/0 encR=   0/0
```

| 字段 | 含义 |
| --- | --- |
| `yaw` | 航向角，单位 **0.1°**，`-1800 ~ +1800` 回绕。断电归零（不做上电绝对航向） |
| `pit` / `rol` | 俯仰 / 横滚角，0.1°，互补滤波（陀螺积分 + 加速度计校正） |
| `gz` | Z 轴角速度，0.1°/s，静止时应在 0 附近小幅抖动 |
| `g` | 陀螺仪就绪标志，1 = 正常 |
| `encL= 12/1234` | 左轮：**10ms 增量** 12 个计数 / **累计** 1234 个计数 |
| `encR= 12/1234` | 右轮，同上 |

**静止判据**：车放桌上不动，`yaw` 在几秒内漂移不应超过 ±1~2 个字（±0.1~0.2°）；`gz` 抖动应在 ±10 以内（±1°/s）。漂得多说明零偏没校准好——把车放着别碰，重新上电。

**转向判据**：手拿车**顺时针**（从上往下看，车头向右转）转 90°，`yaw` 应该**变大**约 900。方向反了就把 `SYSTEM/gyro/gyro.h` 的 `GYRO_YAW_CW_POSITIVE` 改成 0。

### 4.3 零偏校准

`Gyro_Init()` 里自动调 `Gyro_Calibrate()`：静止采 200 次（约 0.4s）求平均当零偏，写进 `gyro_bias_z`。

- **校准期间车必须是静止的**。所以 `Gyro_Init()` 放在 `main()` 的最前面、上电时车还没动。
- 运行中想重校：调用 `Gyro_Calibrate()`（会阻塞约 0.4s，**车必须停着**）。
- 想手动清航向：`Gyro_ZeroYaw()`，`yaw` 立即归零。

### 4.4 航向辅助（`GRAY_GYRO_*`）—— 默认关，三步开启

这是"用陀螺仪帮灰度走直线"的开关。默认 `GRAY_GYRO_ASSIST 0`，**编译进去等于没编译**（代码在 `#if` 里）。

它干的事：灰度算出来的转向量之上，再叠加一个"航向偏离了多少"的修正量。灰度的 `correction > 0` = 左轮快 = 右转，所以航向修正的符号也跟着这个约定走。

| 宏 | 默认 | 含义 |
| --- | --- | --- |
| `GRAY_GYRO_ASSIST` | 0 | 总开关，1 = 启用 |
| `GRAY_GYRO_KP` | 20 | 偏离 1° 给多少修正量（100 = 1°/1°） |
| `GRAY_GYRO_MAX` | 15 | 航向修正的上限，防止抢走灰度的控制权 |
| `GRAY_GYRO_GATE` | 25 | 灰度误差超过这个值就**交出控制权**（进弯道了，让灰度自己拐） |
| `GRAY_GYRO_REF_ERR` | 8 | 灰度误差在这个范围内才更新"直线基准航向" |
| `GRAY_GYRO_REF_LEAK` | 8 | 基准航向每次吸收 1/8 的缓慢漂移 |
| `GRAY_GYRO_SIGN` | -1 | 修正方向；符号错了会直接把车甩出去 |

**开启三步法**（别一步到位）：

1. 先把车架起来（轮子悬空）或手拿住，`GRAY_GYRO_ASSIST 1`、`GRAY_GYRO_KP` 改 5、`GRAY_GYRO_MAX` 改 8，编译烧写。看串口第三行 `yaw` 是否随转动线性变化、静止是否稳定。
2. 放地上跑直道，看车是**更稳**还是**左右摆**。摆 → `KP` 减半；往一边偏且越偏越大 → `GRAY_GYRO_SIGN` 改 1（反过来）。
3. 稳了再逐步把 `KP` 加到 20、`MAX` 加到 15。弯道上如果发现"陀螺仪在跟灰度打架"（进弯迟钝、出弯画龙），把 `GRAY_GYRO_GATE` 从 25 降到 15，让灰度更早接管。

> 只想要"走直线更稳"而循迹已经能跑，这一步完全可以先不做 —— 默认值就是"什么都不改"。

### 4.5 原地转向（给以后用的 API）

```c
Gyro_TurnBy(900, 40, 2000);   /* 原地右转 90°，PWM 上限 40，超时 2000ms */
```

阻塞执行，内部每 10ms 采样一次，`GYRO_TURN_TOL10`（3°）内停，转到超时就放弃。
**V6.0 里没有任何模式调用它**，留着做"走到路口按角度转弯"的备料。

## 5. 增量编码器

### 5.1 为什么两个通道实现不一样

原本想让编码器1 走 TIM8 硬件正交解码（CH1/CH2 = PC6/PC7），但实物板上那两只脚压根没引出来（见第 2 节），于是 **两路统一走 EXTI 软件正交解码**：

- 编码器1（左轮）= PA0 / PA2 → EXTI0 / EXTI2
- 编码器2（右轮）= PA7 / PA8 → EXTI7 / EXTI8（同属 EXTI9_5 组，共用一个中断入口）

两者对外接口完全一样，都是"10ms 增量 + 累计计数"。代价是 CPU：单相约 14.5kHz 时一路 29k 次/秒中断、每次约 2us，两路合计约占 10% CPU —— 5ms 调度扛得住，这也是中断里只做查表累加、不放除法浮点的原因。**如果以后发现计数明显丢步**，正确做法是提高 `ENC_TICK_MS` 或降编码器线数；若哪天确认 PC6/PC7 真能接出来，把 `encoder.h` 的 `ENC1_USE_TIM8` 改回 1 就恢复硬件解码。

### 5.2 三个换算宏（已按本车硬件填好）

松甲手册参数：**13 线霍尔、AB 正交、编码器供电 4.5~5V、输出带上拉**；减速比 1:48 或 1:90。
轮子一圈的计数 = 13 × 减速比 × 4（四倍频）：

| 减速比 | 轮子一圈的计数 | `ENC_CNT_PER_REV` |
| --- | --- | --- |
| **1:48（本车）** | 13 × 48 × 4 = **2496** | **2496** |
| 1:90 | 13 × 90 × 4 = **4680** | 4680 |

| 宏 | 当前值 | 含义 |
| --- | --- | --- |
| `ENC_CNT_PER_REV` | **2496** | 轮子（减速箱之后）转一圈的计数；1:90 的电机写 4680 |
| `ENC_WHEEL_MM` | 65 | 轮子直径，TT 马达标配 65mm 轮 |
| `ENC_GEAR_X10` | 100 | **额外**减速 ×10；2496 已含减速箱，所以保持 100 |

> 等价填法：`ENC_CNT_PER_REV = 52`（13×4，电机轴一圈）+ `ENC_GEAR_X10 = 480`，算出来一样。
> 填 0 时只输出计数、`Encoder_GetSpeedMmS()` 返回 -1。
>
> **最容易错的一点**：换了 1:90 的电机却忘了把 2496 改成 4680，速度会**偏快 1.875 倍**。

### 5.3 校验一遍（可选，1 分钟）

2496 / 4680 是手册算出来的理论值，实际会因为丢步略有偏差，想确认就做一次：

1. 串口第三行记住 `encL` 的**累计**值（斜杠后面那个数）。
2. **手推车让左轮正好转 10 圈**（在轮子上做个记号数圈最准），再记一次累计值。
3. 差值 ÷ 10 应该 ≈ **2496**（1:48）。误差在 ±2% 内就别动它；差得多说明减速比不是 1:48。
4. 顺带验证里程：推车走 1 米，累计计数应 ≈ `1000 / (π × 65) × 2496` ≈ **12220**。

### 5.4 方向不对怎么办

车**往前推**时，`encL`/`encR` 的累计值应该**同时变大**。哪一路变小，就把那一路的 `ENC1_SIGN` / `ENC2_SIGN` 改成 -1（不用拆线、不用改接线）。

## 6. 验证步骤（照着做 5 步）

1. **只烧 V6.0，不动任何宏**。上车电，串口应看到 `[BOOT] ... V6.0` + `gyro ready` + `encoder` 两行。
2. **看 `g`**。没接陀螺仪时 `g=0`、`yaw/pit/rol/gz` 全 0 —— 这**不影响循迹**，V6.0 的控制路径和 V5 一模一样。
3. **按 PC2 切模式**，1/2/3 轮换（或串口发 `1`/`2`/`3`）。模式 3 纯循迹，跟 V5 表现应当完全一致。模式 2 因为没超声波会**原地待命**（不是故障）。
4. **接上陀螺仪**，重上电，确认 `g=1 id=0x68`；手转 90° 看 `yaw` 是否 ±900。
5. **接上编码器**（正极接 **3.3V**，A/B 接 P2 的 PA0/PA2/PA7/PA8），手推车看 `encL/encR` 增量是否随速度变化、方向是否一致；推 1 米后累计值应 ≈ 12220（1:48，65mm 轮）。确认无误后再考虑开 `GRAY_GYRO_ASSIST`（第 4 节三步法）。

## 7. 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `gyro ready = 0`，`id=0x00` 或 `0xFF` | I2C 没通：查 PC0/PC1 有没有接反、模块有没有供电、SDA 有没有上拉（模块一般自带） |
| `id=0x69` | AD0 接了 3.3V，改 `GYRO_I2C_ADDR 0x69` |
| `yaw` 静止时一直涨/一直掉 | 零偏没校准好：车停稳后重新上电；或检查 `GYRO_SAMPLE_MS` 是否真按 10ms 在跑（`[sched] loop=` 那行） |
| 车一开电机 `yaw` 就乱跳 | 电机干扰：MPU6050 尽量远离电机线、SDA/SCL 走短线；必要时把 `GYRO_COMP_ALPHA` 从 98 调到 95 让加速度计多出力 |
| 转 90° 但 `yaw` 只变 -900 | 方向反了：`GYRO_YAW_CW_POSITIVE` 改 0 |
| `encL/encR` 恒为 0 | 编码器没接、或 A/B 没接在 PA0/PA2/PA7/PA8 上；先确认 `[BOOT] encoder` 那行没报错 |
| 一个轮子计数正常、另一个不动 | 右轮两相要在 **PA7（P2 第 4 脚）/ PA8（P2 第 7 脚）**；中断没进来 = 引脚没配成上拉输入、或 EXTI 没开 |
| 计数方向相反 | 改 `ENC1_SIGN` / `ENC2_SIGN` 为 -1 |
| `Encoder_GetSpeedMmS()` 返回 -1 | `ENC_CNT_PER_REV` 被填成了 0，按 5.2 填 2496（1:48）或 4680（1:90） |
| 速度偏大/偏小整数倍 | 减速比填错：1:90 的电机写成 2496 会偏快 1.875 倍；或者把 `ENC_GEAR_X10` 又写成 480（2496 已含减速箱） |
| 计数只有理论值的一半 | A/B 只接通了一相（另一相没插好/断线），或只开了单沿触发 |
| 开了 `GRAY_GYRO_ASSIST` 后车甩 | `GRAY_GYRO_SIGN` 符号反了，先改 1 试；还甩就把 `KP` 降到 5 |
| 模式 2 车不动 | **正常**：超声波已移除（`AVOID_HW_ENABLE=0`），纯避障模式没有测距来源，设计上就是原地待命 |
