# 陀螺仪与编码器（V6.0）

> V6.0 = V5（5ms 调度 + 模式表 + 高速过弯）+ MPU6050 陀螺仪 + 双增量编码器。
> V5 的电机符号、灰度极性、循迹内核一行没动 —— **V5 能跑，V6.0 就还能跑**。
> 两个新模块默认"只测不用"：驱动跑起来、串口能看到数据，但不参与控制。

## 2. 接线表

### 陀螺仪 MPU6050（软件 I2C，PC0/PC1）

| 模块引脚 | 接板子 | 说明 |
| --- | --- | --- |
| VCC | 3.3V | 模块自带 LDO 的话 5V 也行，**不确定就接 3.3V** |
| GND | GND | 共地必须接 |
| SCL | **PC0** | 软件 I2C 时钟 |
| SDA | **PC1** | 软件 I2C 数据 |
| AD0 | GND（或不接） | 接地 = 地址 `0x68`；接 3.3V = `0x69`（要改 `GYRO_I2C_ADDR`） |
| INT | 不接 | 本驱动纯轮询，不用中断 |
| XDA/XCL/XCLR | 不接 | 本驱动不挂从机 |

> 超声波 HC-SR04 原来就是 PC0(TRIG)/PC1(ECHO)，V6.0 起**已被移除**。
> 想恢复超声波：把 `SYSTEM/IRAvoid/IRAvoid.h` 的 `AVOID_HW_ENABLE` 改成 1，
> 但那样就得把陀螺仪从 PC0/PC1 上拔掉（两只模块抢同一对脚）。

### 编码器（PC6~PC9）

| 编码器 | 板子 | 实现方式 | 说明 |
| --- | --- | --- | --- |
| 左轮 A 相 | **PC6** | TIM8_CH1 硬件正交解码 | 4 倍频，方向由硬件判 |
| 左轮 B 相 | **PC7** | TIM8_CH2 | |
| 右轮 A 相 | **PC8** | EXTI8 软件正交解码 | 中断查表，4 倍频 |
| 右轮 B 相 | **PC9** | EXTI9 软件正交解码 | 与 PC8 共用 `EXTI9_5_IRQHandler` |

编码器 VCC 接 **3.3V 或 5V 看编码器型号**（霍尔/光电编码器多数 5V，输出开漏的话请上拉）；
GND 共地。**A/B 两相不要接反到同一只脚上**，接反只会让方向反过来（改 `ENC1_SIGN` / `ENC2_SIGN` 即可，不用拆线）。

## 3. 资源核对（这是最该先看的一节）

### 串口够不够？—— **编码器根本不占串口**

| 资源 | 现状 | 结论 |
| --- | --- | --- |
| USART1（PA9/PA10，板载 CH340G） | 调试口，115200 | 完全不受影响，V6.0 的 BOOT / 三行调试打印都从这走 |
| USART2（PA2/PA3） | 空着 | 想接蓝牙/WiFi 随时能用 |
| USART3（PB10/PB11） | **被灰度传感器 I2C 占着** | 不能用 |
| 编码器 | 只用 GPIO + TIM8 + EXTI | **不占任何串口** |

所以"串口够不够"这个担心可以放下：两个编码器走的是定时器和外部中断，一个串口都不用。

### 引脚

| 引脚 | V5 用途 | V6.0 变化 |
| --- | --- | --- |
| PA1 | 红外遥控 TIM5_CH2 | 不变 |
| PA4 / PA6 | 右电机方向 / LED D4 | 不变 |
| PA9 / PA10 | USART1 TX/RX | 不变 |
| PB0 | 舵机 TIM3_CH3 | 不变 |
| PB1 | 红外避障探头 | 不变 |
| PB6 / PB7 | LED D3 / 左电机方向 | 不变 |
| PB8 / PB9 | 右/左电机 PWM（TIM4） | 不变 |
| PB10 / PB11 | 灰度 I2C | 不变 |
| PC0 / PC1 | 超声波 TRIG/ECHO | **改接 MPU6050 SCL/SDA** |
| PC2 / PC3 | 模式按键 / 蜂鸣器 | 不变 |
| PC6 / PC7 | 空 | **编码器1 A/B（TIM8）** |
| PC8 / PC9 | 空 | **编码器2 A/B（EXTI8/9）** |

### 定时器与中断

| 定时器 | 用途 |
| --- | --- |
| TIM6 | 5ms 节拍（`Sched_Init`），无引脚 |
| TIM4 | 电机 PWM |
| TIM5 | 红外遥控输入捕获 |
| TIM3 | 舵机 50Hz |
| TIM8 | 编码器1 正交解码（CH1/CH2 = PC6/PC7） |
| TIM2 | 随超声波关闭而**空出**，可用 |
| TIM1 / TIM7 | 未用 |

中断：`EXTI9_5_IRQHandler`（PC8/PC9，抢占 1 / 子优先级 1，工程里此前没有这个函数，不冲突）、`EXTI1_IRQHandler`（随超声波一起编译掉）、USART1、TIM5 捕获。

固件体积：V5 = `Code 16370`，V6.0 = `Code 25214`（+8844 字节，大头是 `atan2`/`sqrt` 拉进来的双精度数学库）。Flash 256KB，随便塞。

## 4. 陀螺仪 MPU6050

### 4.1 上电自检

上电后串口会多打两行：

```
[BOOT] gyro ready = 1 id=0x68  (0x68 = MPU6050)
[BOOT] encoder L=0 R=0  second=0
```

- `ready = 0` 或 `id = 0x00 / 0xFF` → **I2C 没通**，先查 PC0/PC1 是否接反、模块有没有供电（0x75 寄存器读不到就是硬件问题，别急着改代码）。
- `id = 0x69` → AD0 接了 3.3V，改成 `#define GYRO_I2C_ADDR 0x69`。
- 上电到 `Sched_Start()` 之间约有 **0.6 秒**用于陀螺仪复位（100ms）+ 零偏校准（200 次 × 2ms），这段时间车是不动的，属正常。

### 4.2 调试第三行怎么读

`app_mode_debug_task` 每 200ms 打三行，第三行是 V6.0 新增：

```
yaw=   -3 pit=   1 rol=   0 gz=    2 | g=1 encL=   0/0 encR=   0/0
```

| 字段 | 含义 |
| --- | --- |
| `yaw` | 航向角，单位 **0.1°**，`-1800 ~ +1800` 回绕。断电归零（不做上电绝对航向） |
| `pit` / `rol` | 俯仰 / 横滚角，0.1°，互补滤波（陀螺积分 + 加速度计校正） |
| `gz` | Z 轴角速度，0.1°/s，静止时应在 0 附近小幅抖动 |
| `g` | 陀螺仪就绪标志，1 = 正常 |
| `encL= 12/1234` | 左轮：**10ms 增量** 12 个计数 / **累计** 1234 个计数 |
| `encR= 12/1234` | 右轮，同上 |

**静止判据**：车放桌上不动，`yaw` 在几秒内漂移不应超过 ±1~2 个字（±0.1~0.2°）；`gz` 抖动应在 ±10 以内（±1°/s）。漂得多说明零偏没校准好——把车放着别碰，重新上电。

**转向判据**：手拿车**顺时针**（从上往下看，车头向右转）转 90°，`yaw` 应该**变大**约 900。方向反了就把 `SYSTEM/gyro/gyro.h` 的 `GYRO_YAW_CW_POSITIVE` 改成 0。

### 4.3 零偏校准

`Gyro_Init()` 里自动调 `Gyro_Calibrate()`：静止采 200 次（约 0.4s）求平均当零偏，写进 `gyro_bias_z`。

- **校准期间车必须是静止的**。所以 `Gyro_Init()` 放在 `main()` 的最前面、上电时车还没动。
- 运行中想重校：调用 `Gyro_Calibrate()`（会阻塞约 0.4s，**车必须停着**）。
- 想手动清航向：`Gyro_ZeroYaw()`，`yaw` 立即归零。

### 4.4 航向辅助（`GRAY_GYRO_*`）—— 默认关，三步开启

这是"用陀螺仪帮灰度走直线"的开关。默认 `GRAY_GYRO_ASSIST 0`，**编译进去等于没编译**（代码在 `#if` 里）。

它干的事：灰度算出来的转向量之上，再叠加一个"航向偏离了多少"的修正量。灰度的 `correction > 0` = 左轮快 = 右转，所以航向修正的符号也跟着这个约定走。

| 宏 | 默认 | 含义 |
| --- | --- | --- |
| `GRAY_GYRO_ASSIST` | 0 | 总开关，1 = 启用 |
| `GRAY_GYRO_KP` | 20 | 偏离 1° 给多少修正量（100 = 1°/1°） |
| `GRAY_GYRO_MAX` | 15 | 航向修正的上限，防止抢走灰度的控制权 |
| `GRAY_GYRO_GATE` | 25 | 灰度误差超过这个值就**交出控制权**（进弯道了，让灰度自己拐） |
| `GRAY_GYRO_REF_ERR` | 8 | 灰度误差在这个范围内才更新"直线基准航向" |
| `GRAY_GYRO_REF_LEAK` | 8 | 基准航向每次吸收 1/8 的缓慢漂移 |
| `GRAY_GYRO_SIGN` | -1 | 修正方向；符号错了会直接把车甩出去 |

**开启三步法**（别一步到位）：

1. 先把车架起来（轮子悬空）或手拿住，`GRAY_GYRO_ASSIST 1`、`GRAY_GYRO_KP` 改 5、`GRAY_GYRO_MAX` 改 8，编译烧写。看串口第三行 `yaw` 是否随转动线性变化、静止是否稳定。
2. 放地上跑直道，看车是**更稳**还是**左右摆**。摆 → `KP` 减半；往一边偏且越偏越大 → `GRAY_GYRO_SIGN` 改 1（反过来）。
3. 稳了再逐步把 `KP` 加到 20、`MAX` 加到 15。弯道上如果发现"陀螺仪在跟灰度打架"（进弯迟钝、出弯画龙），把 `GRAY_GYRO_GATE` 从 25 降到 15，让灰度更早接管。

> 只想要"走直线更稳"而循迹已经能跑，这一步完全可以先不做 —— 默认值就是"什么都不改"。

### 4.5 原地转向（给以后用的 API）

```c
Gyro_TurnBy(900, 40, 2000);   /* 原地右转 90°，PWM 上限 40，超时 2000ms */
```

阻塞执行，内部每 10ms 采样一次，`GYRO_TURN_TOL10`（3°）内停，转到超时就放弃。
**V6.0 里没有任何模式调用它**，留着做"走到路口按角度转弯"的备料。

## 5. 增量编码器

### 5.1 为什么两个通道实现不一样

STM32F103 只有一个还没被占用的正交解码定时器（TIM8），而 TIM8 的 CH1/CH2 正好落在 PC6/PC7。所以：

- **编码器1（左轮）= TIM8 硬件正交解码**：精度高、零 CPU 开销、方向由硬件判定。
- **编码器2（右轮）= EXTI 软件正交解码**：PC8/PC9 各挂一个双边沿中断，中断里查 4×4 正交表累加。

两者对外接口完全一样，都是"10ms 增量 + 累计计数"。软件解析的那一路在高速时中断会变多（每 10ms 几百次），但每相 1000 线的编码器 × 4 倍频 × 减速比，实际中断率仍在几千 Hz 量级，5ms 节拍扛得住。**如果以后发现右轮计数明显丢步**，把 `ENCODER` 的两路对调（改成左轮走 EXTI）没意义，正确做法是降编码器线数或提高 `ENC_TICK_MS`。

### 5.2 三个宏必须标定（否则速度是错的）

| 宏 | 默认 | 含义 |
| --- | --- | --- |
| `ENC_CNT_PER_REV` | **0** | 轮子转一圈产生多少个计数（4 倍频后的数） |
| `ENC_WHEEL_MM` | 65 | 轮子直径，毫米 |
| `ENC_GEAR_X10` | 100 | 减速比 ×10（100 = 1:1，电机直连轮子） |

**`ENC_CNT_PER_REV` 默认是 0，此时 `Encoder_GetSpeedMmS()` 返回 -1（明确表示"没标定"），不会给你一个假速度。** 增量和累计计数照常可用。

### 5.3 标定步骤（3 分钟）

1. 串口第三行记住 `encL` 的**累计**值（斜杠后面那个数）。
2. 手推车（或让车走）**让左轮正好转 10 圈**，再记一次累计值。
3. `ENC_CNT_PER_REV = (后 - 前) / 10`。右轮同理（`encR`），两轮取同一个值（同型号编码器装法一样）。
4. 量轮子直径填 `ENC_WHEEL_MM`；有减速箱就填 `ENC_GEAR_X10`（减速比 ×10）。
5. 验证：车走 1 米，累计计数应 ≈ `1000 / (π × D) × ENC_CNT_PER_REV × 减速比`。

### 5.4 方向不对怎么办

车**往前推**时，`encL`/`encR` 的累计值应该**同时变大**。哪一路变小，就把那一路的 `ENC1_SIGN` / `ENC2_SIGN` 改成 -1（不用拆线、不用改接线）。

## 6. 验证步骤（照着做 5 步）

1. **只烧 V6.0，不动任何宏**。上车电，串口应看到 `[BOOT] ... V6.0` + `gyro ready` + `encoder` 两行。
2. **看 `g`**。没接陀螺仪时 `g=0`、`yaw/pit/rol/gz` 全 0 —— 这**不影响循迹**，V6.0 的控制路径和 V5 一模一样。
3. **按 PC2 切模式**，1/2/3 轮换（或串口发 `1`/`2`/`3`）。模式 3 纯循迹，跟 V5 表现应当完全一致。模式 2 因为没超声波会**原地待命**（不是故障）。
4. **接上陀螺仪**，重上电，确认 `g=1 id=0x68`；手转 90° 看 `yaw` 是否 ±900。
5. **接上编码器**，手推车看 `encL/encR` 增量是否随速度变化、方向是否一致。标定完 `ENC_CNT_PER_REV` 后，把 `GRAY_GYRO_ASSIST` 保持 0，先照第 4 节的三步法单独验证陀螺仪辅助。

## 7. 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `gyro ready = 0`，`id=0x00` 或 `0xFF` | I2C 没通：查 PC0/PC1 有没有接反、模块有没有供电、SDA 有没有上拉（模块一般自带） |
| `id=0x69` | AD0 接了 3.3V，改 `GYRO_I2C_ADDR 0x69` |
| `yaw` 静止时一直涨/一直掉 | 零偏没校准好：车停稳后重新上电；或检查 `GYRO_SAMPLE_MS` 是否真按 10ms 在跑（`[sched] loop=` 那行） |
| 车一开电机 `yaw` 就乱跳 | 电机干扰：MPU6050 尽量远离电机线、SDA/SCL 走短线；必要时把 `GYRO_COMP_ALPHA` 从 98 调到 95 让加速度计多出力 |
| 转 90° 但 `yaw` 只变 -900 | 方向反了：`GYRO_YAW_CW_POSITIVE` 改 0 |
| `encL/encR` 恒为 0 | 编码器没接、或者 A/B 接的是 PC6~PC9 之外；先确认 `[BOOT] encoder` 那行没报错 |
| 一个轮子计数正常、另一个不动 | 检查 PC8/PC9 是否被别的模块占（V6.0 里没有）；软件那一路的中断没进来 = 引脚没配成上拉输入或 EXTI 没开 |
| 计数方向相反 | 改 `ENC1_SIGN` / `ENC2_SIGN` 为 -1 |
| `Encoder_GetSpeedMmS()` 返回 -1 | `ENC_CNT_PER_REV` 还是 0，按 5.3 标定 |
| 开了 `GRAY_GYRO_ASSIST` 后车甩 | `GRAY_GYRO_SIGN` 符号反了，先改 1 试；还甩就把 `KP` 降到 5 |
| 模式 2 车不动 | **正常**：超声波已移除（`AVOID_HW_ENABLE=0`），纯避障模式没有测距来源，设计上就是原地待命 |
