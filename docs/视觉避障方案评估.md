# 用 K210（亚博）做视觉避障 —— 可行性评估与集成方案

> 结论先说：**可行，而且在你这条"白纸黑线 + 摆放障碍"的场地上，视觉比单点超声波更适合做"往左还是往右"的决策。**
> 但**不建议纯视觉单干**：单目测距在 30cm 以外的误差会明显放大，建议做成
> **「超声波/红外负责"有没有、有多近" + K210 负责"哪边空、往哪绕"」的融合方案**，
> 或者先做纯视觉最小闭环，跑通后再决定要不要加回超声波。

---

## 1. 为什么视觉在这个场景里有优势

| 维度 | 超声波（HC-SR04 等） | 单点红外避障 | **K210 视觉** |
|---|---|---|---|
| 探测视野 | ±15°锥角（很窄） | ±10~20° | **60~70° 水平视场** |
| 能否判断"左空还是右空" | ❌ 只有一个数 | ❌ | ✅ 天然能看到左右 |
| 输出信息量 | 1 个距离值 | 1 个开关量 | 障碍位置/大小/类别/左右空隙 |
| 距离精度 | **±3mm（很高）** | 阈值式 | 单目 30cm 内约 ±3~5cm，1m 外误差大 |
| 受光照影响 | 无 | 无 | **有**（弱光/反光会失效） |
| 受材质影响 | 软质/斜面吸收差 | 颜色影响 | 颜色/纹理影响（可训练鲁棒） |
| 延迟 | ~20ms | <1ms | **50~80ms**（采集+推理+串口） |
| 算力占用 | 几乎为 0 | 0 | K210 独立承担，STM32 不负重 |

你现在的痛点恰好是"**只有一个正前方探头，无法判断往左还是往右**"（见 `docs/调参手册.md` §2），
这正是视觉最擅长补的短板。

---

## 2. 推荐架构：K210 做感知节点，STM32 做控制

```
┌─────────────────────┐        UART 115200/921600        ┌──────────────────────┐
│   K210（亚博板）     │  6 字节定长帧（障碍标志/距离/方向） │   STM32F103（主控）   │
│  · OV2640 摄像头     │ ───────────────────────────────→ │  · IRAvoid 状态机     │
│  · MaixPy / C 程序   │                                  │  · 循迹 PID（IRSEARCH）│
│  · 色块/YOLO/地面分割│                                  │  · 电机 PWM           │
└─────────────────────┘                                  └──────────────────────┘
        ↑ 5V 供电（独立 LDO，别跟电机共用）                       ↑ 原有循迹、遥控不变
```

**为什么不让 K210 直接驱动电机**：K210 是"视觉 + 少量 IO"的芯片，缺少你现在的
PWM 电机层、循迹 PID、遥控解码；而且视觉帧率 20~30fps，做实时控制太慢。
让 K210 只输出"结构化感知结果"，STM32 保持 100Hz 控制环，是最稳的分工。

## 3. 硬件接线

### 3.1 串口（推荐 USART2）

| K210 引脚 | 接 STM32 | 说明 |
|---|---|---|
| TX（UART2_TX） | **PA3**（丝印 IO0，USART2_RX） | 交叉连接 |
| RX（UART2_RX） | **PA2**（丝印 IO1，USART2_TX） | 可选，只发不收也能用 |
| GND | GND | **必须共地** |

- 两边都是 3.3V TTL，**不用电平转换**
- PA2/PA3 不是 5V 容忍脚，但 K210 是 3.3V 输出，安全
- 波特率建议 **115200**（稳）或 **921600**（够快，但线长要短）

> 为什么不用 USART3（PB10/PB11）：那两个脚现在被灰度传感器的 I2C 占用。
> 为什么不用 USART1（PA9/PA10）：那是接 CH340 的调试口，要留给电脑看日志。

### 3.2 供电

- K210 + 摄像头峰值电流 **300~500mA**，一定要**单独一路 5V**（板上 AMS1117 那路给单片机用的别抢）
- 电机启动瞬间会把 5V 拉低，K210 容易复位 → 建议 K210 用**单独电池或独立 LDO**
- 上电顺序：先 K210 启动（约 2s），STM32 延后初始化串口

### 3.3 安装

- 摄像头装车头，**俯角 10~20°**，高度约 8~12cm（能同时看到近处地面和前方障碍）
- 加减震（海绵/硅胶柱），否则电机振动会让画面糊、帧率掉
- 别挡住灰度板（循迹还要用）

## 4. 通信协议（建议）

定长 6 字节，简单、好调试：

```
偏移  含义
 0    0xAA        帧头1
 1    0x55        帧头2
 2    flags       bit0=检测到障碍  bit1=左侧空  bit2=右侧空  bit3=置信度低
 3    dist_cm     障碍距离（厘米，0~255；0=无效）
 4    dir         建议转向：0=直行 1=左转 2=右转 3=停车
 5    crc         前面 5 字节异或
```

STM32 端解析伪代码：

```c
/* 收到一帧后 */
if (frame[0]==0xAA && frame[1]==0x55 && crc_ok(frame))
{
    vision_ok    = 1;
    vision_flag  = frame[2];
    vision_dist  = frame[3];
    vision_dir   = frame[4];
    vision_stamp = HAL_GetTick();   /* 用于超时判断 */
}
```

**超时保护**：超过 200ms 没收到有效帧 → 视为"视觉失效"，自动退回超声波/红外逻辑。

## 5. K210 端算法选型（按难度递增）

| 方案 | 实现 | 帧率（QVGA） | 适用 |
|---|---|---|---|
| **色块检测** | MaixPy `find_blobs`，找特定颜色障碍 | 25~40fps | 障碍颜色固定（比如红色锥桶） |
| **地面分割** | 阈值分割 + 每列最低点 → 障碍在左/中/右 | 20~30fps | 障碍颜色不定但地面单一（白纸） |
| **YOLO v2 tiny** | 自训练小模型，识别"障碍/人/车" | 10~15fps | 需要分类、鲁棒性要求高 |
| **AprilTag/Aruco** | 贴标记，精确位姿 | 30fps | 能接受在障碍上贴码 |

### 距离怎么来（单目的核心难点）

| 方法 | 公式 | 精度 | 前提 |
|---|---|---|---|
| 地面假设（推荐） | `d = f·H / (y_img − y_horizon)` | 30~80cm 内 ±5cm | 障碍**贴地**，标定 f、H、地平线 |
| 已知尺寸 | `d = f·W_real / W_pixel` | 依赖物体尺寸假设 | 障碍宽度大致固定 |
| 双目/ToF | — | 最好 | 需要额外硬件 |

> 若用地面假设，标定方法：把障碍摆在 20/40/60/80cm，记录 bbox 底边 y 坐标，拟合一条直线即可。

## 6. 延迟与速度预算（能不能刹得住）

```
摄像头采集(Grab)   ~30ms（30fps）
推理/处理          ~10~30ms
串口传输 6 字节     ~0.5ms @115200
─────────────────────────────
合计               ~50~70ms
```

| 车速 | 60ms 内行进距离 | 结论 |
|---|---:|---|
| 0.3 m/s（约 30% PWM） | 1.8 cm | ✅ 完全够 |
| 0.5 m/s | 3 cm | ✅ 够 |
| 1.0 m/s | 6 cm | ⚠️ 需要提前量，建议限速 |

你现在的避障直线速度是 `AVOID_BASE_SPEED=60`（约 0.4~0.5 m/s），**在安全范围内**。

## 7. 与现有代码的集成方式（改动很小）

`IRAvoid.c` 现在是"读 PB1 电平 → 状态机"。加一个**来源选择宏**即可：

```c
/* IRAvoid.h */
#define AVOID_SRC_GPIO      0   /* 0 = 原来的 PB1 数字探头（红外/超声波开关量） */
#define AVOID_SRC_VISION    1   /* 1 = K210 串口视觉 */

#define AVOID_SRC           AVOID_SRC_GPIO
```

- `AVOID_SRC == AVOID_SRC_VISION` 时：
  - 增加 `USART2` 初始化 + 接收中断/轮询解析（PA2/PA3）
  - `AVoidRun()` 里用 `vision_flag / vision_dist / vision_dir` 替代 `AVOID_IO`
  - **转向方向不再写死**，直接用 `vision_dir`（这就是视觉最大的价值）
  - 保留原来的两级转弯 + 回正状态机（逻辑不用重写）
- 视觉失效（200ms 无帧）→ 自动降级到 GPIO 探头

> 涉及文件：`SYSTEM/IRAvoid/IRAvoid.c/.h`、`USER/main.c`（初始化）、`USER/Template.uvprojx`（若要新增文件）。
> 建议新增 `SYSTEM/vision/vision.c/.h` 单独管串口协议，`IRAvoid` 只消费结果。

## 8. 风险清单（按严重度）

| 风险 | 影响 | 对策 |
|---|---|---|
| **单目测距不准** | 误判距离，撞上 | 只用视觉判断"左/右"，距离交给超声波；或用融合 |
| **光照变化** | 白天/阴影/反光导致漏检 | 加补光 LED；用 YOLO 而非纯阈值；保留超声波兜底 |
| **延迟** | 高速来不及 | 限速 ≤0.5m/s；提高帧率（降分辨率到 QVGA/QQVGA） |
| **供电不足** | K210 反复重启 | 独立 5V、加大电容、电机与 K210 分开供电 |
| **振动** | 画面糊 | 减震安装、缩短曝光 |
| **K210 生态** | 已停产，资料慢慢变少 | 现有板子够用；代码/模型本地备份 |
| **双串口占用** | PA2/PA3 被占 | 已确认空闲；USART3 被灰度 I2C 占用，别再动 |

## 9. 建议的实施节奏

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **v4.0（最小闭环）** | K210 跑色块/地面分割 → 串口发 6 字节帧；STM32 解析并驱动现有状态机 | 车看到障碍能自动往空的一侧绕 |
| **v4.1（融合）** | 超声波给距离、视觉给方向；或互为兜底 | 强光/黑暗下仍能避障 |
| **v4.2（优化）** | 转向力度随距离自适应；记录误判并调参 | 连续绕 10 个障碍不碰撞 |

## 10. 需要你确认的几件事

1. **现在车上的"超声波"具体是哪种**：
   - HC-SR04（需要 Trig/Echo 两个脚 + 微秒计时）？→ 现有代码读的是 PB1 数字量，**对不上**，需要我补超声波驱动
   - 还是"超声波避障模块"（输出高低电平，像红外一样）？→ 现在的 `AVOID_IO` 就能直接用
2. **K210 板子型号**（亚博的哪一款：Maix Bit / Maix Dock / 专用扩展板）？决定摄像头型号和固件
3. **障碍物是固定的吗**（比如锥桶/纸箱）？颜色固定的话，色块方案 20 行 MaixPy 就能跑
4. 你希望先做 **纯视觉** 还是 **视觉+超声波融合**？

## 附：K210 端最小参考代码（MaixPy 伪代码）

```python
import sensor, image, time
from machine import UART

sensor.reset(); sensor.set_pixformat(sensor.RGB565)
sensor.set_framesize(sensor.QVGA); sensor.skip_frames(30)
uart = UART(2, 115200)

def crc(b): 
    c = 0
    for x in b: c ^= x
    return c

while True:
    img = sensor.snapshot()
    # 例：找红色障碍，取最大色块
    blobs = img.find_blobs([(30, 100, 15, 80, 10, 60)], area_threshold=300)
    if blobs:
        b = max(blobs, key=lambda x: x.pixels())
        # 用底边 y 估距离（需标定）
        dist = max(0, min(255, int(calib(b.y() + b.h()))))
        # 左右空隙：障碍中心 x 与画面中心比较
        if b.cx() < img.width()*0.4:   d = 1   # 障碍偏左 → 往右
        elif b.cx() > img.width()*0.6: d = 2   # 障碍偏右 → 往左
        else:                          d = 3 if dist < 25 else 1
        flags = 1
    else:
        flags = 0; dist = 0; d = 0
    f = bytes([0xAA, 0x55, flags, dist, d])
    uart.write(f + bytes([crc(f)]))
```
