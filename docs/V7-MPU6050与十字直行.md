# V7：MPU6050 接线 + 十字路口默认直行

> 这一版解决两件事：
> ① 接入 MPU6050（陀螺仪），得到航向角 `yaw`；
> ② **十字路口默认直行** —— 进十字锁航向，出来后继续直行一段时间，
>    不再一丢线就原地打转。

---

## 1. 先纠正一个说法：MPU6050 不走串口

MPU6050 / GY-521 是 **I2C** 器件，只有 SCL/SDA 两根线，**不占任何 USART**。

本工程的串口已经排满了：

| 串口 | 用途 | 能不能动 |
|---|---|---|
| USART1 (PA9/PA10) | 调试口（CH340G→USB） | 不能动，调参靠它 |
| USART2 (PA2/PA3) | 预留给 K210 视觉 | 不能动 |

所以你不用纠结"放哪个串口"，只有 I2C 引脚可选。

> 如果你买的是 **JY901 / JY61 那种 TX/RX 串口模块**，那是另一套协议，
> 接到 USART2 上也能做，但代码完全不同 —— 把型号告诉我再补。

## 2. 接线

### 2.1 默认引脚：PC4 / PC5

```
GY-521 VCC  →  5V      （模块自带 3.3V LDO，接 3.3V 也行）
GY-521 GND  →  GND
GY-521 SCL  →  PC4
GY-521 SDA  →  PC5
GY-521 AD0  →  GND     （地址 0x68；接 3.3V 就变 0x69，代码里要改）
GY-521 INT  →  不接
```

### 2.2 为什么不用灰度模块那两根（PB10/PB11）

灰度模块的 **PULL 跳线是 5V 上拉**，总线空闲电平就是 5V。
MPU6050 的 SCL/SDA 是 3.3V 器件、**不耐 5V**，直接并到同一条总线上有烧片风险。

所以这里单独开了一条**软件 I2C**（任意两个空闲 IO 都行），和灰度互不影响。

### 2.3 PC4/PC5 没引出来怎么办

只改 `SYSTEM/imu/imu.h` 顶上这 5 个宏就行（两个脚必须在同一个端口）：

```c
#define IMU_SCL_GPIO        GPIOC
#define IMU_SCL_PIN         GPIO_Pin_4
#define IMU_SDA_GPIO        GPIOC
#define IMU_SDA_PIN         GPIO_Pin_5
#define IMU_GPIO_RCC        RCC_APB2Periph_GPIOC
```

| 备选 | 引脚 | 备注 |
|---|---|---|
| 1 | PB12 / PB13 | 都在 GPIOB，改 `RCC_APB2Periph_GPIOB` |
| 2 | PA5 / PA7 | 都在 GPIOA，改 `RCC_APB2Periph_GPIOA` |

**不要用**：PB10/PB11（灰度 5V 上拉）、PA2/PA3（留给 K210）、
PB3/PB4（JTAG）、PA13/PA14（SWD 下载，改了会连不上仿真器）。

## 3. 上电标定（很重要）

`Imu_Init()` 会上电后**静止采集 1.5 秒**，取平均值当零偏（bias）。

- 这 1.5 秒内**车必须完全静止**，不能碰、不能放桌上晃；
- 串口会打印 `[BOOT] imu ok (id=0x68, bias=xxx)`，`bias` 以 0.01°/s 为单位；
- 标定完 `yaw` 归零，之后靠积分累加。

**判断零偏好不好**：静止放 30 秒，看调试行 `yaw=` 漂多少。

- 漂 < 1°：很好；
- 漂 1~3°：可用（十字里几百毫秒，误差可忽略）；
- 漂 > 5°：标定时车动了，或者模块供电不稳，重上电再来一次。

---

## 4. 方向标定（只做一次）

装好后手拿车**左转 90°**，看串口 `yaw`：

- 数值变大（+90 左右）→ 不用改；
- 数值变小（−90 左右）→ 把 `imu.h` 里 `IMU_YAW_SIGN` 改成 `-1`，重新编译。

约定：**左转为正**，和灰度误差"负数 = 线在左"是同一套方向感。

---

## 5. 十字路口为什么"默认直行"

原来的问题不是"不知道是十字"，而是：

1. 8 路全黑时加权重心恰好是 0 → 看起来"很正"，其实是"很对称"（V6 已用覆盖度识别成 `EV_WIDE`）；
2. **很多赛道的十字中间是断线/白缝**，车开上去一两帧就变成"丢线"，
   于是走 `EV_LOST` 原地找线 —— 车就在十字中间原地打转，这就是"过不去"的真相。

V7 的做法：

```
进 EV_WIDE
   ├─ 锁存 yaw（陀螺当前角度）
   ├─ 期间不走 PID，只用 (yaw − yaw_hold) 做航向修正
   └─ 走完宽黑，记下"刚出十字"
        └─ 之后 GRAY_COAST_MS(250ms) 内若丢线
              → 继续按航向直行，不找线
        └─ 保护时间过了还丢线 → 才允许原地找线（原来的逻辑）
```

效果：**进十字是斜的，出来还是同一个角度**；中间的缝直接趟过去。

没有接陀螺时（`Imu_IsReady()==0`）自动退化成 V6 的"锁 0 直行"，
航向修正恒为 0，不影响原来的调参。

## 6. 新增的三个参数（串口可调）

| 参数 | 默认 | 含义 |
|---|---:|---|
| `CROSSK` | 30 | 航向修正 P：每偏 0.1° 给 0.3 个速度单位（即 3 单位/度） |
| `CROSSD` | 10 | 航向死区，单位 0.1°（10 = 1.0° 内不修正，防抖） |
| `COAST` | 250 | 出宽黑后"继续直行"的保护时间（ms） |

调法：

- 十字里**左右摆**：`CROSSK` 调小（30→20）；
- 十字里**纠不回来**（出来还是歪的）：`CROSSK` 调大（30→45）；
- 十字中间**顿一下**：`COAST` 调大（250→400）；
- 十字后**该找线却直冲**：`COAST` 调小（250→150）。

```text
> ?
[cfg] BASE=60 GAIN=40 FAR=60 THD=30 KD=12 KI=0
[cfg] SLOW=20 SLOWD=40 MIN=25 REV=45 CUT=180 FULL=55 REF=60
[cfg] RAMP=120 WIDE=7 DEAD=2 CROSSK=30 CROSSD=10 COAST=250
[cfg] src=FLASH
> CROSSK 40
> SAVE
```

> 注意：参数版本从 1 升到 2，**旧的存档会失效**（自动回默认值），
> 升级后需要重新 `SAVE` 一次。

## 7. 调试字段

```
mode=1 L=  60 R=  60 | err=   0 corr=   0 spd= 60 ev=WIDE act=8 cc=3 yaw=  -2 | ready=1 ...
                                                              ↑ 十字次数  ↑ 航向角(度)
```

| 字段 | 看什么 |
|---|---|
| `yaw` | 静止应该不动；转弯应该跟着变；不跟着变就是方向/接线有问题 |
| `ev=WIDE` + `cc` | 过十字时 `cc` +1；直线上乱加说明 `WIDE` 太小 |
| `err=998` | **新增**：十字后保护期内的短暂丢线（不是故障，正在直行通过） |
| `err=999` | 真丢线，正在找线 |

## 8. 自检

模式 4 现在有 8 步，第 7 步是陀螺：

```
[TEST] 步骤7/8 陀螺（静止时 yaw 应该基本不动）...
[TEST] imu ok  id=0x68  bias=-12(0.01dps)  yaw=0
```

失败时打印的是排错清单：SCL/SDA 是否接反、AD0 是否接 GND、模块有没有 5V。

## 9. 已知边界

- **yaw 会漂**：纯积分，没有绝对参考。静止久了会漂几度，跑一圈几百秒通常 <3°，
  对"过十字走直线"够用；
- **不能当罗盘用**：上电时车头指向就是 0°，只做相对角度；
- **剧烈颠簸/撞车**会让积分跳一下，保护期内的直行会偏一点点，跑完这一段就恢复；
- 想做"定角找线"（丢线后转 120° 再换方向），接口已经在了，下一步再加。
