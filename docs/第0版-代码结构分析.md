# ZYSTM32-A0 智能小车综合程序 —— 代码结构分析

> 分析对象：`3.案例代码/10、ZYSTM32-A0智能小车黑线循迹、避障、遥控实验综合程序`
> 源文件为 GBK 编码；本文所有行号对应原文件的物理行号。

---

## 0. 一句话结论

这是一个 **"裸机 + 超级循环（super-loop）"** 的 STM32F103 例程：`main()` 里一个 `while(1)` 不断做
「读按键 → 切模式 → 执行对应实验函数」，三个实验（循迹 / 避障 / 遥控）只负责**采传感器 + 发运动指令**，
真正的电机输出全部收敛到底层一套 `ZYSTM32_xxx()` 运动函数里。
整体是 **三层结构 + 三条并列的业务线 + 一条运动执行链**。

```
                    ┌──────────────────────────────────────────┐
   应用层            │  main.c : KeyScanTask / LEDTask / IR_IN  │  ← 模式调度
                    └───────────────┬──────────────────────────┘
          ┌─────────────────┬───────┴────────┬──────────────────┐
   业务层 │ IRSEARCH.c 循迹 │ IRAvoid.c 避障 │ remote.c 遥控解码 │
          └─────────────────┴───────┬────────┴──────────────────┘
                                    │  只调用 ZYSTM32_run/back/Left/Right/Spin/brake
                    ┌───────────────┴──────────────────────────┐
   执行层            │  motor.c : 运动函数 → SetMotorSpeed       │  ← 唯一的执行出口
                    │          → TIM4 PWM(CH3/CH4) + 方向 GPIO  │
                    └───────────────┬──────────────────────────┘
                    ┌───────────────┴──────────────────────────┐
   支撑层            │ delay.c(SysTick) / sys.c(位带) / keysacn  │
                    │ usart.c(printf，本工程未使用)             │
                    └──────────────────────────────────────────┘
                    CMSIS + STM32F10x_FWLib（标准外设库，无需改动）
```

## 2. 软件分层

| 层 | 内容 | 依赖 |
|---|---|---|
| L4 应用/调度 | `main()`、`KeyScanTask()`、`LEDTask()`、`IR_IN()` | 所有业务层 |
| L3 业务逻辑 | `SearchRun()`、`AVoidRun()`、`Remote_Scan()` | motor + 传感器宏 |
| L2 执行/驱动 | `ZYSTM32_run/back/Left/Right/Spin_Left/Spin_Right/brake`、`SetMotorSpeed`、`TIM4_PWM_Init`、`Remote_Init`、`IRSearchInit`、`IRAvoidInit`、`KEY_Init`、`delay_*` | FWLib |
| L1 库/内核 | `stm32f10x_gpio/tim/rcc/misc/usart`、CMSIS、startup | — |

关键约定：**L3 及以下不允许直接写 GPIO/TIM 寄存器**，对外只暴露"跑/退/左/右/自转/停"这种**语义化动作**。
这是这个例程最值得学的设计点——传感器逻辑和电机硬件完全解耦。

## 3. 启动流程与主循环

### 3.1 初始化序列（`main.c:100-110`）

```
main()
 ├─ delay_init()            SysTick 时钟源 = HCLK/8 = 9MHz，fac_us=9
 ├─ KEY_Init()              PC2 按键(IPU) / PC3 蜂鸣器 / PB6 LED_D3 / PA6 LED_D4
 ├─ IRSearchInit()          PA7、PB0 循迹探头(IPU)
 ├─ IRAvoidInit()           PB1 避障探头(IPU)
 ├─ TIM4_PWM_Init(7199,0)   TIM4 CH3(PB8)/CH4(PB9) → 10kHz PWM
 │                          同时把 PB7/PA4 配成推挽输出(方向脚)
 ├─ Remote_Init()           PA1 红外输入，TIM5 CH2 输入捕获，1MHz 计数
 ├─ ZYSTM32_brake(500)      上电停 500ms（防止乱冲）
 ├─ keyMode = KEYMODE_1     默认进入"循迹"模式
 └─ while(1) { KeyScanTask(); LEDTask(); }
```

### 3.2 主循环的本质

```
        ┌──────────────┐
        │ KeyScanTask  │  检测 PC2 下降沿 → keyMode 1→2→3→1 循环（软件消抖靠"按住不放"标志）
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │   LEDTask    │  switch(keyMode)：
        └──────┬───────┘   1 → SearchRun()   循迹，D4亮/D3灭
               │           2 → AVoidRun()    避障，D4灭/D3亮(障碍时)
               │           3 → IR_IN()       遥控，D4/D3全亮
               ▼
         回 while 顶部
```

- **没有任何 OS、没有中断任务**，所有节奏都由 `delay_ms()` 阻塞产生（见 §7 时序分析）。
- 一次循环 ≈ 10ms（循迹/避障正常态）或最长 ≈ 1.2s（避障动作中）。

## 4. 三大功能模块拆解

### 4.1 循迹模块（IRSEARCH）—— 双探头"跨线"循迹

**硬件**：2 路红外反射式光电对管，分别接 **PA7(右)**、**PB0(左)**，上拉输入。
电平定义：`WHITE_AREA=0`（白底反射 → 低）、`BLACK_AREA=1`（黑线吸收 → 高）。

**决策表（`IRSEARCH.c:25-43`）—— 布尔真值表式，没有中间量：**

| 左探头 PB0 | 右探头 PA7 | 判定 | 动作 | 实际效果 |
|:--:|:--:|---|---|---|
| 白 0 | 白 0 | 线在两探头**中间**（正常） | `ZYSTM32_run(50,10)` | 直行 |
| 黑 1 | 白 0 | 线偏**左** | `ZYSTM32_Left(50,10)` | 左轮停、右轮走 → 车头左摆 |
| 白 0 | 黑 1 | 线偏**右** | `ZYSTM32_Right(50,10)` | 右轮停、左轮走 → 车头右摆 |
| 黑 1 | 黑 1 | 十字/横线/丢线 | `ZYSTM32_brake(10)` | 停车 |

**控制律 = 纯开关量（Bang-Bang）**：要么直行、要么单轮停转，**没有比例调节、没有速度差**，速度固定写死 50。
采样周期 = 决策 + 动作 = 10ms → 理论上 100Hz 闭环，但每次都要等 `delay_ms(10)` 走完才采下一次。

**一句话概括**：`传感器1bit → 转向指令` 的查表法，属于"能跑通的最小循迹"。

### 4.2 避障模块（IRAvoid）—— 单探头开环避障

**硬件**：1 路红外避障探头 → **PB1**，上拉输入。`BARRIER_Y=0`（有障碍，输出低）、`BARRIER_N=1`（无障碍）。

```
AVoidRun()
 ├─ 无障碍：ZYSTM32_run(50,10)         直行，蜂鸣器停、D3灭
 └─ 有障碍：BEEP_SET; LED_D3_SET        声光提示
          ├─ ZYSTM32_brake(300)         原地停车 300ms
          ├─ ZYSTM32_back(50,400)       倒车 400ms
          └─ ZYSTM32_Left(50,500)       左转 500ms  ← 固定往左打
```

**特征**：完全 **开环 + 定时**，靠"倒多久、转多久"碰运气；避障动作期间 **1.2 秒看不到前方**，
且动作序列执行时不会重新检测障碍（阻塞在 `delay_ms` 里）。掉头方向写死向左，遇到凹形障碍会来回打转。

### 4.3 遥控模块（remote）—— NEC 协议红外解码

**硬件**：PA1 接红外接收头（HS0038 之类），**TIM5_CH2 输入捕获**。
`PSC=72-1 → 1MHz`（1us 计一个数），`ARR=10000`（10ms 溢出）。

**解码原理（`remote.c:75-132` 中断里完成）：**

| NEC 时序 | 捕获到的高电平宽度 | 程序判定 |
|---|---|---|
| 引导码 | 4.5ms 高（前有 9ms 低） | `RmtSta |= 1<<7` 标记收到引导码 |
| 数据位 0 | 560us | `Dval>300 && <800` → `RmtRec<<=1; |=0` |
| 数据位 1 | 1680us | `Dval>1400 && <1800` → `RmtRec<<=1; |=1` |
| 重复码 | 2.5ms | `RmtCnt++`（连按计数），清溢出计数 |
| 按键松开 | 连续 15 次 10ms 溢出（≈150ms 无沿） | 清引导码标志 |

`RmtRec`(u32) 存 32 位：`地址 | 地址反码 | 键值 | 键值反码`。
`Remote_Scan()`（`remote.c:138`）做三重校验：地址反码、键值反码、`ID==0`，通过才返回键值（命令字节），否则 0。

**键值 → 动作映射（`main.c:14-29` `IR_IN()`）**

| 键值(dec) | 十六进制 | 遥控器按键 | 动作 |
|---:|---|---|---|
| 98 | 0x62 | `CH`（前进） | `ZYSTM32_run(80,100)` |
| 168 | 0xA8 | `FFA857`（音量+） | `ZYSTM32_back(80,100)` 后退 |
| 34 | 0x22 | `VOL-`（左转） | `ZYSTM32_Left(80,100)` |
| 194 | 0xC2 | `CH+`（右转） | `ZYSTM32_Right(80,100)` |
| 2 | 0x02 | `⏸`（暂停） | `ZYSTM32_brake(100)` |
| 224 | 0xE0 | `|◀◀` 上一曲 | `ZYSTM32_Spin_Left(80,100)` 原地左旋 |
| 144 | 0x90 | `▶▶|` 下一曲 | `ZYSTM32_Spin_Right(80,100)` 原地右旋 |

（遥控器键值表见光盘 `1.学前先看/STM32遥控器按键表.jpg`，为 **FFxxyy** 格式的 NEC 码；程序只取中间字节。）

**注意控制律**：`IR_IN()` 每帧先 `brake(10)` 再读键，动作又固定 100ms ⇒ 按住前进键时实际是
**走 100ms → 停 10ms → 再走 100ms**，占空比约 91%，肉眼看会略有顿挫，且**松手后仍会再执行完一次 100ms 动作**。

### 4.4 模式调度（按键 + 灯语）

`KEYMODE_1=循迹 / KEYMODE_2=避障 / KEYMODE_3=遥控`，PC2 每按一次循环切换。

```
KeyScanTask():  keypre==0 && 按下 → keypre=1，keyMode 1→2→3→1
                松开 → keypre=0（边沿检测，无定时消抖）
```

| 模式 | LED D4 (PA6) | LED D3 (PB6) | 说明 |
|---|:--:|:--:|---|
| 1 循迹 | 亮 | 灭 | |
| 2 避障 | 灭 | 由 `AVoidRun` 控制 | D3 被"借用"成障碍指示灯（有障碍亮），模式指示被覆盖 |
| 3 遥控 | 亮 | 亮 | |

> 灯语设计上 D3 在模式2里语义冲突，是这套例程的一个小瑕疵。

## 5. 执行层：电机运动库（最核心的 60 行）

### 5.1 硬件通路

- **PWM**：TIM4，`ARR=7199, PSC=0` → 72MHz/7200 = **10kHz**；CH3→PB8、CH4→PB9，**PWM2 模式 + 高极性**。
- **方向脚**：左轮 `PB7`、右轮 `PA4`（推挽输出）。
- 四驱底盘实为 **左右两组并联驱动**（4 个轮子，只有 2 路 PWM + 2 个方向脚）。
- `PWM2 模式` ⇒ 输出高电平时间 = `ARR+1-CCR`，所以程序用 **反着写** 的方式给占空比：

```c
sPWM = 7201 - fabs(cSpeed)*72;      // cSpeed ∈ [-100,100]，单位：百分比
duty = (7200 - sPWM) / 7200 ≈ |cSpeed| %
```

| cSpeed | CCR | 占空比 |
|---:|---:|---:|
| 100 | 1 | 99.99% |
| 50 | 3601 | 50% |
| 0 | 7201(>ARR) | 0（彻底关闭） |

### 5.2 运动函数语义（`motor.c:128-184`）

| 函数 | 左轮 | 右轮 | 结果 | 备注 |
|---|---|---|---|---|
| `ZYSTM32_run(speed,ms)` | `-speed` | `+speed` | 直行 | 左右极性相反，靠方向脚区分 |
| `ZYSTM32_back(speed,ms)` | `100-speed` | `-(100-speed)` | 后退 | ⚠️ 速度用 `100-speed`，**参数含义与其它函数不一致**：`back(80)` 实际只有 20 的速度 |
| `ZYSTM32_Left(speed,ms)` | 0 | `+speed` | 绕左轮左转 | 左轮停 |
| `ZYSTM32_Right(speed,ms)` | `-speed` | 0 | 绕右轮右转 | 右轮停 |
| `ZYSTM32_Spin_Left(speed,ms)` | `+speed` | `+speed` | 原地左旋 | 左轮反转、右轮正转 |
| `ZYSTM32_Spin_Right(speed,ms)` | `-speed` | `-speed` | 原地右旋 | 左轮正转、右轮反转 |
| `ZYSTM32_brake(ms)` | 0 | 0 | 停车并拉低两方向脚 | 停车时长 = `delay_ms(ms)` |

方向脚极性（由 `SetMotorSpeed` 推出）：**左轮正转 = PB7 低，右轮正转 = PA4 低；两者都高 = 后退**。

所有运动函数都是 **"设置速度 → 阻塞等待 time 毫秒"**，没有"设置后立即返回"的接口 ——
这是整个工程"只能开环定时"的根源。

### 5.3 ⚠️ 命名与通道交叉（读代码时最容易踩的坑）

| 宏名（motor.h） | 实际引脚 | TIM4 通道 |
|---|---|---|
| `LEFT_MOTOR_GO` | PB7 | — |
| `LEFT_MOTOR_PWM` | **PB8** | **CH3** |
| `RIGHT_MOTOR_GO` | PA4 | — |
| `RIGHT_MOTOR_PWM` | **PB9** | **CH4** |

但 `SetMotorSpeed` 里：**`case 0`（注释"右轮"）→ `TIM_SetCompare3`（PB8）**；
**`case 1`（注释"左轮"）→ `TIM_SetCompare4`（PB9）**。

也就是说程序实际认定的配对是 **「右轮 = PA4 方向 + PB8 PWM」「左轮 = PB7 方向 + PB9 PWM」**，
与 `RIGHT_MOTOR_PWM/LEFT_MOTOR_PWM` 这两个宏的命名**正好相反**。
另外 `motor.h:23-29` 的注释（LEFT_MOTOR_GO PB8 / PWM PB9 / RIGHT_MOTOR_GO PA6 / RIGHT_MOTOR_PWM PB10）
与真实 `#define` 又是第三套说法，**三处不一致**。

→ 实车能直行，说明底板就是 `PA4+PB8 / PB7+PB9` 这两组配对，**错的是宏名和注释，不是程序**。
但以后若按宏名去改代码（比如顺手写 `RIGHT_MOTOR_PWM_SET`），就会改到另一路电机。
**建议以 `5.原理图/ZYSTM32-A0原理图.pdf` 为准统一命名。**

## 7. 时序分析（为什么它"能动但不好用"）

所有动作都是**阻塞**的，主循环周期取决于当前动作：

```
循迹正常 : 采样(<1ms) + run(50,10)      → 循环 ≈ 10ms
循迹丢线 : 采样 + brake(10)             → 循环 ≈ 10ms
避障正常 : 采样 + run(50,10)            → 循环 ≈ 10ms
避障触发 : 300+400+500 = 1.2s 全阻塞   → 期间按键无效、无法重新探测
遥控     : brake(10) + 动作 100ms       → 循环 ≈ 110ms
模式切换 : 只有等当前动作做完才轮到 KeyScanTask
```

后果：
1. **按键延迟**：在避障动作中按模式键，最多要等 1.2s 才响应。
2. **遥控顿挫**：见 §4.3，每帧 10ms 刹车。
3. **采样率被动作时间绑架**：想提高循迹响应速度只能改 `time` 参数，改小又会让 PWM 频繁重设。
4. 定时全靠 `delay_ms`，**无法并行处理多个传感器**（这是后续要升级成"定时器节拍 + 状态机"的直接原因）。

## 9. 如果要继续做（这个例程的升级路线）

按"改动量从小到大"排：

1. **修注释/宏名**（§5.3、§8-11），十分钟的事，但能避免后面接错线。
2. **把阻塞动作拆成非阻塞**：`ZYSTM32_xxx` 只设速度，另加 `motor_tick()` 用 TIM 中断或主循环计数到时间再停。
   → 按键立刻变灵敏，三种模式可以真正并行（循迹时也能被遥控打断）。
3. **循迹升级 PID**：把两个开关量探头换成灰度/多路模拟量（光盘 `赛事工程/灰度传感器` 目录里有资料），
   按 `误差 = 左权重 - 右权重` 输出左右轮差速：`L = base - K*e, R = base + K*e`。
4. **避障升级**：红外换成超声波/多路红外，动作改成"后退到安全距离 → 转向选择空隙大的一侧"。
5. **遥控加"持续控制"**：`RmtCnt` 已经在统计连按次数（repeat code），可用来做"按住持续前进"，
   松开后 150ms 内自动停。
6. **（进阶）上 FreeRTOS/时间片**：光盘 `8.STM32学习资料/12，FreeRTOS学习资料` 有现成材料。
