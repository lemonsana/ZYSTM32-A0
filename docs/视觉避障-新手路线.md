# 纯视觉避障：给"完全不懂视觉"的人的路线图

> 你的情况：有 K210（亚博）、朋友说用 YOLO、你没接触过视觉。
> 这篇文档不讲论文，只讲**你要做什么、按什么顺序做、每步大概多久**。

---

## 1. 先想清楚：视觉模块到底要给小车什么？

不管用 YOLO 还是色块，K210 最终只输出 **3 个数字**，通过串口发给 STM32：

| 输出 | 含义 | 例子 |
|---|---|---|
| `flag` | 前方有没有障碍 | 1 = 有 |
| `dir` | 障碍在画面**偏左 / 中间 / 偏右** | 0=左，1=中，2=右 |
| `conf` | 置信度（可选） | 0~100 |

STM32 拿到后就三个动作：偏左 → 往右绕；偏右 → 往左绕；居中 → 按距离决定转多急。

**所以"视觉避障"这件事，90% 的难度在 K210 端"怎么稳定地找出障碍"，10% 在串口传输。**
YOLO 只是"找出障碍"的其中一种方法，不是唯一方法，也不是最简单的方法。

---

## 2. YOLO 到底是什么（大白话）

**YOLO 不是"库"，是一个"训练出来的模型"。** 它不像 `#include <math.h>` 那样加上就能用。

| 说法 | 实际情况 |
|---|---|
| "用 YOLO 就能识别障碍" | ❌ 前提是这个模型**见过**你的障碍物 |
| "YOLO 是库，调一下就行" | ❌ 需要：收集图片 → 标注 → 训练 → 转换格式 → 部署 |
| "K210 能跑 YOLO" | ✅ 能，但只能跑**特别小的版本**（YOLOv2-tiny），QVGA 下约 10~15fps |

**跑 YOLO 的完整流程（你需要做的活）：**

```
① 拍 300~1000 张照片（含各种障碍物、各种角度、各种光线）
        ↓  1~2 天
② 用工具画框标注（labelImg / MaixHub 在线标注）
        ↓  半天
③ 训练（本地 GPU 或 MaixHub 云端，K210 只能跑不能训）
        ↓  1~3 小时
④ 转成 K210 能吃的 .kmodel 格式（nncase 工具）
        ↓
⑤ 拷到 TF 卡，写 MaixPy 代码调用
```

**门槛总结**：不是"写几行代码"，而是"攒一个数据集 + 训练一轮"。对第一次做的人，**顺利也要 3~5 天**，
而且遇到光照变化、障碍物换样子就要重新标注重训。

## 3. 三条路线对比（先选对再动手）

| 路线 | 原理 | 开发时间 | 鲁棒性 | 前置条件 | 适合谁 |
|---|---|---|---|---|---|
| **① 色块检测** | 在图像里找"某个颜色范围"的连通区域 | **半天~1 天** | 中（颜色固定时很好） | 障碍物颜色固定且与背景差异大 | ✅ **强烈推荐先做** |
| ② 模板匹配 | 拿一张障碍物照片去图像里"找相似图案" | 1 天 | 低（旋转/缩放就失效） | 障碍物外观固定 | 特定场景 |
| ③ **YOLO** | 训练好的神经网络，输出框和类别 | **3~5 天** | 高（可识别多种、抗光照） | 数据集 + 训练环境 | 障碍物种类多/不可控 |

**你的场景**：白纸黑线赛道 + 摆几个障碍物。**障碍物颜色基本固定**（锥桶、纸箱、积木），
背景是白纸——这是**色块检测的完美场景**，不需要 YOLO。

> 朋友说得没错，YOLO 是"正经"做法，但它是**给障碍物千变万化的场景**准备的。
> 你现在做的是"固定场地 + 固定障碍"，用 YOLO 属于高射炮打蚊子，还会把调试周期从 1 天拉到 1 周。

## 4. 推荐路线图

| 阶段 | 做什么 | 周期 | 验收 |
|---|---|---|---|
| **v4.0** | K210 跑**色块检测** → 串口发 3 个数字 → STM32 绕行 | 1~2 天 | 车看到红/黄色障碍能往空的一侧绕 |
| **v4.1** | 加入"距离估计"（障碍框大小 → 远近），分级转弯 | 1 天 | 近处障碍转得更急 |
| **v4.2** | 如果色块不够用（障碍变色/光照差），再上 **YOLO** | 3~5 天 | 识别率、光照稳定性提升 |

**先用色块把整条链路（K210→串口→STM32→电机）跑通**，这是最重要的。
链路通了以后，把色块换成 YOLO 只是"换掉中间那段代码"，其他都不用动。

## 5. K210 端：从零到跑通色块

### 5.1 环境（30 分钟）

1. 电脑装 **MaixPy IDE**（或 VS Code + MaixPy 插件）
2. K210 刷 **MaixPy 固件**（亚博/矽速官网下载对应板型的 .kfpkg，用 kflash 烧）
3. 插 USB，设备管理器出现串口 → IDE 连接 → 能跑 `print("hello")` 就成功

### 5.2 第一段代码：摄像头发图（10 分钟）

```python
import sensor, image, lcd
sensor.reset()
sensor.set_pixformat(sensor.RGB565)
sensor.set_framesize(sensor.QVGA)      # 320x240
sensor.set_vflip(1)                     # 摄像头装反了加这句
sensor.set_hmirror(1)
sensor.skip_frames(time=2000)
lcd.init()
while True:
    img = sensor.snapshot()
    lcd.display(img)                    # 屏幕上看实时画面
```

### 5.3 第二段代码：色块检测（核心，20 行）

```python
import sensor, image
sensor.reset()
sensor.set_pixformat(sensor.RGB565)
sensor.set_framesize(sensor.QVGA)
sensor.skip_frames(time=2000)

# 颜色阈值 [L_min, L_max, A_min, A_max, B_min, B_max]  （LAB 色彩空间）
# 红色示例；具体数值用 MaixPy IDE 的"阈值编辑器"现场取
RED = [(30, 80, 20, 70, 0, 60)]

while True:
    img = sensor.snapshot()
    blobs = img.find_blobs(RED, area_threshold=500, merge=True)
    if blobs:
        b = max(blobs, key=lambda x: x.pixels())   # 取最大的色块
        img.draw_rectangle(b.rect(), color=(0,255,0))
        if b.cx() < img.width() * 0.4:      dir = 0   # 偏左
        elif b.cx() > img.width() * 0.6:    dir = 2   # 偏右
        else:                               dir = 1   # 中间
        print("flag=1 dir=%d area=%d" % (dir, b.pixels()))
    else:
        print("flag=0")
```

> **取阈值的方法**：MaixPy IDE 有"阈值编辑器"，把障碍物放镜头前，拖动滑块直到画面里
> 只有障碍物变色、背景全黑，把 6 个数抄下来即可。这一步 10 分钟。

### 5.4 串口发送（10 分钟）

```python
from machine import UART
uart = UART(2, 115200)          # K210 的 UART2 = P11(TX) / P10(RX)，视板型而定

def send(flag, d):
    f = bytes([0xAA, 0x55, flag, d])
    uart.write(f + bytes([f[0]^f[1]^f[2]^f[3]]))
```

协议和 STM32 端约定（见下节）。

## 6. 和 STM32 联调

### 6.1 接线

| K210 | STM32 |
|---|---|
| TX | **PA3**（IO0，USART2_RX） |
| RX | **PA2**（IO1，USART2_TX）（可只接 TX→PA3 单向） |
| GND | GND（必须共地） |
| 5V | 独立 5V（别和电机共用） |

### 6.2 协议（4 字节，简单可靠）

```
AA 55 | flags | dir | XOR校验
  flags: bit0 = 检测到障碍
  dir:   0=偏左  1=居中  2=偏右
```

### 6.3 联调步骤

1. 先只接 K210 的 TX → STM32 的 PA3，串口助手里看 K210 发了什么（可先用 USB-TTL 验证）
2. STM32 端解析后，在原来的调试串口（PA9/PA10，115200）打印 `vis: flag=1 dir=0`
3. 打印正常后，再把 dir 接到避障状态机

> STM32 侧代码我来写：`vision.c/h` + `IRAvoid` 增加 `AVOID_SRC_VISION` 分支，
> 状态机、两级转弯、回正全部复用。

## 7. 什么时候才真的需要 YOLO

满足下面任意两条，再考虑 YOLO：

- [ ] 障碍物颜色不固定（有时红、有时蓝、有时反光）
- [ ] 需要区分"可撞的/不可撞的"（比如识别锥桶 vs 人）
- [ ] 场地光照变化大（室内外切换、有阴影）
- [ ] 色块方案误检率 > 20%

**YOLO 入门路径**（到时候再看）：
1. 用 **MaixHub**（矽速官方在线平台）上传标注好的图片，网页上直接训练，产出 .kmodel
2. 把 .kmodel 拷到 TF 卡
3. MaixPy 里用 `maix.nn.YOLOv2` 加载推理
4. 训练数据量：每类 ≥ 300 张，含不同角度/光照

## 8. 常见坑

| 坑 | 表现 | 解决 |
|---|---|---|
| 摄像头装反 | 画面上下颠倒 | `set_vflip(1)` / `set_hmirror(1)` |
| 光照变化 | 阈值白天好用、晚上失效 | 加补光 LED；或用 YOLO |
| 色块粘连 | 障碍和背景混在一起 | 调窄阈值；开 `merge=True` 前先腐蚀 |
| K210 重启 | 跑着跑着一会儿又重启 | 供电不足，独立 5V + 加 470µF 电容 |
| 串口乱码 | STM32 收到乱码 | 波特率不一致 / 没共地 |
| 帧率太低 | 卡顿 | 降到 QQVGA(160x120)，关掉 LCD 显示 |

---

## 9. 一句话总结

**先用色块（1 天跑通全链路），别一上来啃 YOLO。**
YOLO 是"障碍物不可控"时的终极方案，不是入门方案；等色块真的不够用，再按第 7 节升级。
